# TEAM_STYLE.md

## What we care about
- Add unit tests for helper functions.
- Consider using appropriate design patterns where applicable.
- Break functions into smaller, manageable pieces.
- Include comprehensive documentation for modules.
- Add inline comments to clarify complex lines of code.
- Implement logging before and after critical operations to monitor behavior.
- Use context managers for file and database operations to ensure proper resource management.
- Validate input before writing to the database to maintain data integrity.
- Replace magic numbers with named constants for better readability.
- Use parameterized queries to prevent SQL injection vulnerabilities.
- Surround API calls with specific exception handling to manage errors effectively.
- Utilize descriptive variable names instead of single-letter names for clarity.

## What we ignore
- Adding type hints to every local variable is not prioritized.
- Extracting repeated logic into helper functions is deemed unnecessary.
- Manual index tracking should not be replaced with enumerate.
- Guard clauses to reduce nesting depth are not favored.
- Preference for pathlib.Path over os.path for file operations is not required.
- F-strings for string formatting are not mandated.
- Adding type hints to public function signatures is not a team requirement.
- Returning structured JSON errors from API endpoints is not practiced.

## Naming conventions
- Use descriptive variable names that clearly indicate the purpose of the variable.
- Avoid single-letter variable names unless within a very limited scope (e.g., loop indices).

## Error handling
- Implement specific exception handling around API calls to gracefully manage potential failures.
- Always validate input data to ensure robust error handling during database operations.

# TEAM_STYLE.md

## What we care about
- Consider using design patterns where applicable.
- Break functions into smaller, manageable pieces to enhance readability.
- Include inline comments for complex or non-obvious lines of code.
- Implement logging before and after critical operations for better traceability.
- Utilize `enumerate` to avoid manual index tracking in loops.
- Validate inputs before writing to the database to ensure data integrity.
- Replace magic numbers with named constants for clarity.
- Use parameterized queries to prevent SQL injection vulnerabilities.
- Handle specific exceptions around API calls to improve robustness.
- Use descriptive variable names instead of single-letter identifiers for better understanding.

## What we ignore
- Adding unit tests for helper functions is not prioritized.
- Type hints on every local variable are not required.
- Additional documentation for modules is deemed unnecessary.
- Extracting repeated logic into helper functions is not favored.
- Guard clauses for reducing nesting depth are not needed.
- Prefer usage of `pathlib.Path` over `os.path` for file operations is not a priority.
- F-strings for string concatenation are not mandated.
- Type hints for public function signatures are not emphasized.

## Naming conventions
- Use clear and descriptive names for variables and functions.
- Avoid using single-letter names; prefer names that convey meaning.

## Error handling
- Use specific exception handling for external API calls rather than generic handlers.
- Ensure that input validation is included to minimize unexpected errors during operations.

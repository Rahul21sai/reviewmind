# TEAM_STYLE.md

## What we care about
- Break functions into smaller pieces for clarity.
- Add inline comments to explain complex lines.
- Implement logging before and after critical operations.
- Extract repeated logic into helper functions to reduce duplication.
- Use `enumerate` for better readability instead of manual index tracking.
- Employ guard clauses to minimize nesting depth in code.
- Prefer `pathlib.Path` over `os.path` for file operations for improved usability.
- Utilize f-strings for string formatting instead of concatenation.
- Return structured JSON errors from API endpoints for consistency.
- Use context managers for file and database operations to ensure proper resource management.
- Validate inputs before writing to the database to prevent errors.
- Replace magic numbers with named constants for clarity.
- Use parameterized queries to prevent SQL injection attacks.
- Include specific exception handling around API calls for robustness.
- Opt for descriptive variable names rather than single letters to enhance code readability.

## What we ignore
- Adding unit tests for helper functions.
- Considering design patterns that aren't clearly beneficial.
- Adding type hints to every local variable.
- Increasing documentation without clear necessity.
- Adding type hints to public function signatures.
- Repeated recommendations for unit tests for helper functions.

## Naming conventions
- Use meaningful, descriptive names for variables and functions.
- Avoid single-letter variable names except in very specific contexts (e.g., loop indices).

## Error handling
- Always handle errors gracefully with specific exceptions, especially in API calls.
- Ensure structured JSON errors are returned from API endpoints for clear communication with clients.

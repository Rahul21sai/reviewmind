# TEAM_STYLE.md

## What we care about
- **Design Patterns**: Consider using a design pattern for complex solutions.
- **Function Size**: Break functions into smaller pieces for better readability.
- **Inline Comments**: Add comments to clarify complex lines of code.
- **Logging**: Implement logging before and after critical operations for traceability.
- **Enumeration**: Use `enumerate` instead of manual index tracking in loops.
- **Guard Clauses**: Prefer guard clauses to reduce nesting depth and improve clarity.
- **File Operations**: Use `pathlib.Path` rather than `os.path` for handling file paths.
- **String Formatting**: Utilize f-strings over string concatenation for better readability.
- **API Response Errors**: Return structured JSON errors from API endpoints for consistency.
- **Context Managers**: Apply context managers for file and database operations to ensure proper resource management.
- **Input Validation**: Always validate input before writing to the database to enhance security.
- **Named Constants**: Replace magic numbers with named constants to improve code clarity.
- **Parameterised Queries**: Use parameterised queries to prevent SQL injection attacks.
- **Specific Exception Handling**: Implement specific exception handling around API calls to gracefully manage errors.
- **Descriptive Names**: Use descriptive variable names instead of single-letter identifiers.

## What we ignore
- **Unit Tests**: Adding unit tests for helper functions is not a priority at this time.
- **Type Hints**: We do not require type hints for every local variable or public function signature.
- **Module Documentation**: Additional module documentation is not deemed necessary unless it significantly enhances understanding.

## Naming conventions
- Use clear and descriptive variable names.
- Avoid single-letter variable names unless in very short loops (e.g., `i`, `j` in iterations).

## Error handling
- Return structured JSON errors from APIs.
- Handle exceptions specifically in API calls to maintain robustness and improve user feedback.

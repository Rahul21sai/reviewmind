# TEAM_STYLE.md

## What we care about
- Add inline comments explaining complex or critical lines of code.
- Implement logging before and after critical operations for traceability.
- Extract repeated logic into helper functions to reduce redundancy.
- Use `enumerate()` to avoid manual index tracking.
- Incorporate guard clauses to minimize nesting depth.
- Prefer `pathlib.Path` over `os.path` for file system operations.
- Utilize f-strings for improved readability in string formatting.
- Include type hints in public function signatures for clarity.
- Return structured JSON errors from API endpoints for consistency.
- Use context managers when performing file and database operations.
- Validate inputs prior to database writes to ensure data integrity.
- Replace magic numbers with named constants for better readability.
- Use parameterized queries to prevent SQL injection vulnerabilities.
- Provide specific exception handling around API calls for robustness.
- Choose descriptive variable names instead of single letters for clarity.

## What we ignore
- Add unit tests for helper functions (overload).
- Consider using a design pattern (too abstract).
- Add type hints to every local variable (unnecessary).
- Break functions into smaller pieces (may hinder readability).
- Expand documentation in modules (overemphasis on documentation).

## Naming conventions
- Use descriptive names reflecting variable or function purpose.
- Avoid abbreviations except for well-known acronyms.

## Error handling
- Focus on structured error responses in APIs.
- Emphasize specific exception handling rather than generic catch-all approaches.

# TEAM_STYLE.md

## What we care about
- Add logging before and after critical operations.
- Extract repeated logic into helper functions.
- Use `enumerate` instead of manual index tracking.
- Add guard clauses to reduce nesting depth.
- Use f-strings instead of string concatenation.
- Return structured JSON errors from API endpoints.
- Use context managers for file and database operations.
- Add input validation before database writes.
- Replace magic numbers with named constants.
- Use parameterised queries to prevent SQL injection.
- Add specific exception handling around API calls.
- Add unit tests for this helper function.
- Add type hints to every local variable.

## What we ignore
- Extraneous text in sensitive values (e.g., `GITHUB_WEBHOOK_SECRET`).
- Redundant suggestions for unit tests or breaking functions into smaller pieces.
- Generic recommendations for design patterns or increased documentation.
- Inline comments that do not add significant value.
- Preference for `pathlib.Path` over `os.path`.

## Naming conventions
- Use descriptive and meaningful names for variables and functions.
- Follow consistent naming patterns (e.g., snake_case for variable names).

## Error handling
- Implement structured logging for error conditions.
- Use specific exception handling to capture and resolve anticipated failures.
- Ensure API endpoints return clear and structured error responses in JSON format.

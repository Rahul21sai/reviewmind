# TEAM_STYLE.md

## What we care about
- **Unit Tests**: Always add unit tests for helper functions and critical operations.
- **Design Patterns**: Consider and implement appropriate design patterns.
- **Type Hints**: Include type hints for every local variable to enhance code clarity.
- **Function Modularity**: Break larger functions into smaller, manageable pieces.
- **Documentation**: Add comprehensive documentation for modules and inline comments to clarify complex logic.
- **Logging**: Implement logging before and after critical operations to trace execution.
- **Helper Functions**: Extract repeated logic into helper functions for reusability.
- **Enumerate Usage**: Use `enumerate` for iterating with counters instead of manual index tracking.
- **File Operations**: Prefer `pathlib.Path` over `os.path` for improved handling of file paths.
- **Input Validation**: Ensure input validation is performed before database writes.
- **Magic Numbers**: Replace magic numbers with named constants for better readability.
- **SQL Queries**: Use parameterized queries to prevent SQL injection risks.
- **Exception Handling**: Implement specific exception handling around API calls.

## What we ignore
- Comments that may cause confusion about sensitive values during deployment, such as those at the end of the `GITHUB_WEBHOOK_SECRET` value.
- Suggestions to reduce nesting depth with guard clauses.
- Preference for f-strings over string concatenation.
- Adding type hints to public function signatures.
- Returning structured JSON errors from API endpoints.
- Use of context managers for file and database operations.
- The use of descriptive variable names over single letters.

## Naming conventions
- Use descriptive names for variables, functions, and constants to convey intent clearly.

## Error handling
- Implement specific exception handling as required, particularly around external services and database interactions. Always be cautious of potential failure points and handle them gracefully.

# TEAM_STYLE.md

## What we care about
- Break functions into smaller pieces for clarity and maintainability.
- Add inline comments to explain complex lines of code.
- Implement logging before and after critical operations to track flow and errors.
- Extract repeated logic into helper functions to adhere to DRY principles.
- Use `enumerate` instead of manual index tracking for cleaner code.
- Add guard clauses to reduce nesting depth and improve readability.
- Prefer `pathlib.Path` over `os.path` for file operations to leverage modern Python features.
- Use f-strings instead of string concatenation for better readability and performance.
- Add type hints to public function signatures to enhance clarity and tooling support.
- Return structured JSON errors from API endpoints for consistent error handling.
- Use context managers for file and database operations to ensure proper resource management.
- Add input validation before database writes to prevent integrity issues.
- Replace magic numbers with named constants for improved code readability.
- Use parameterized queries to prevent SQL injection vulnerabilities.
- Add specific exception handling around API calls to ensure robust error management.

## What we ignore
- Adding unit tests for helper functions is not a team priority.
- Consideration of design patterns is not necessary unless explicitly stated.
- Adding type hints to every local variable is seen as unnecessary.
- Additional documentation is not prioritized unless it significantly clarifies complex modules.

## Naming conventions
- Use descriptive and meaningful names for functions and variables that clearly convey their purpose.

## Error handling
- Always handle errors specifically and gracefully, focusing on predictable failures and providing structured responses.

# TEAM_STYLE.md

## What we care about
- Consider using a design pattern here.
- Break functions into smaller, manageable pieces.
- Add inline comments for clarity on complex lines.
- Implement logging before and after critical operations.
- Use `enumerate` to simplify index tracking.
- Return structured JSON errors from API endpoints.
- Validate inputs before writing to the database.
- Replace magic numbers with named constants.
- Use parameterized queries to prevent SQL injection.
- Employ specific exception handling around API calls.
- Choose descriptive variable names over single letters.

## What we ignore
- Adding unit tests for helper functions.
- Type hints for every local variable.
- Additional documentation for modules deemed clear.
- Extracting repeated logic into helper functions.
- Adding guard clauses to minimize nesting depth.
- Replacing `os.path` with `pathlib.Path` for file operations.
- Using f-strings instead of string concatenation.
- Type hints for public function signatures.

## Naming conventions
- Use descriptive names that convey the purpose of variables and functions.
- Avoid single-letter names, except for loop counters.

## Error handling
- Always return structured JSON errors from API calls.
- Implement specific exception handling tailored to potential failure points.

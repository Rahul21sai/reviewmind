# TEAM_STYLE.md

## What we care about
- **Unit Testing**: Always add unit tests for helper functions.
- **Design Patterns**: Consider utilizing appropriate design patterns where applicable.
- **Code Modularity**: Break large functions into smaller, manageable pieces.
- **Documentation**: Add comprehensive documentation for each module.
- **Inline Comments**: Always include inline comments to clarify complex lines of code.
- **Logging**: Implement logging before and after critical operations to aid in troubleshooting.
- **Input Validation**: Validate inputs before writing to the database to maintain data integrity.
- **Named Constants**: Replace magic numbers with named constants for better readability.
- **SQL Security**: Use parameterized queries to prevent SQL injection attacks.
- **Exception Handling**: Implement specific exception handling for all API calls.

## What we ignore
- Comments that may cause confusion during deployment (e.g., sensitive information comments).
- Mandating type hints for every local variable.
- Extracting repeated logic into helper functions unless deemed necessary for clarity.
- Preference for using `enumerate` over manual index tracking.
- Adding guard clauses solely to reduce nesting depth.
- Preference for using `pathlib.Path` over `os.path` for file operations.
- Using f-strings instead of string concatenation in cases where clarity is maintained.

## Naming conventions
- Use clear, descriptive names for variables, functions, and classes.
- Use camelCase for function names and variables.
- Class names should be in PascalCase.

## Error handling
- Implement specific error messages for different types of errors.
- Avoid using generic exceptions to ensure effective troubleshooting.
- Always log the error details for future reference and debugging.

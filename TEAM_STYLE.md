# TEAM_STYLE.md

## What we care about
- Use of design patterns when applicable.
- Breaking down functions into smaller, manageable pieces.
- Adding inline comments to clarify complex lines of code.
- Implement logging before and after critical operations.
- Utilizing `enumerate` for loops to avoid manual index tracking.
- Reducing nesting depth by employing guard clauses.
- Preferring `pathlib.Path` over `os.path` for file operations.
- Using f-strings for string formatting instead of concatenation.
- Returning structured JSON errors from API endpoints.
- Validating input before writing to the database.
- Replacing magic numbers with named constants.
- Utilizing parameterized queries to prevent SQL injection.
- Adding specific exception handling around API calls.
- Opting for descriptive variable names instead of single-letter names.

## What we ignore
- Adding unit tests for helper functions (focused on primary functionalities).
- Type hints for every local variable (only relevant for public interfaces).
- Additional documentation beyond essential explanations.
- Extracting repeated logic into helper functions if it doesn't enhance clarity.
- Type hints for public function signatures unless specifically warranted.
- Context managers for file and database operations (team preference for clarity).

## Naming conventions
- Use clear and descriptive variable names.
- Avoid using single-letter variable names except for loop counters.

## Error handling
- Implement specific exception handling for API calls.
- Ensure input validation prior to database writes.
- Return structured JSON responses for error cases from APIs.

# TEAM_STYLE.md

## What we care about
- **Unit Testing**: Always add unit tests for helper functions.
- **Design Patterns**: Consider applicable design patterns to improve code structure.
- **Type Hints**: Add type hints to every local variable for better code clarity.
- **Function Size**: Break large functions into smaller, manageable pieces.
- **Documentation**: Enhance modules with comprehensive documentation.
- **Inline Comments**: Provide inline comments to clarify complex lines of code.
- **Logging**: Implement logging before and after critical operations to track processes.
- **Helper Functions**: Extract repeated logic into reusable helper functions.
- **Input Validation**: Always validate input before writing to the database.
- **Named Constants**: Replace magic numbers with descriptive named constants.
- **SQL Security**: Use parameterized queries to mitigate SQL injection risks.
- **Exception Handling**: Implement specific exception handling around API calls.

## What we ignore
- Confusing comments, especially related to sensitive values (e.g., GITHUB_WEBHOOK_SECRET).
- Use of `enumerate` for index tracking is not preferred; manual index tracking is acceptable.
- Guard clauses to reduce nesting depth are not necessary.
- Preferably avoid `os.path` in favor of `pathlib.Path` for file operations.
- String concatenation should be replaced with f-strings.
- While type hints for public function signatures could enhance clarity, the team prefers to focus on local variable type hints.
- Structured JSON error responses from API endpoints are not prioritized.

## Naming conventions
- Use descriptive names that reflect the purpose and functionality of variables and functions. 
- Follow a consistent convention; use `snake_case` for functions and variables.

## Error handling
- Ensure specific error handling is added around external calls (e.g., APIs).
- Validate all inputs to prevent unexpected errors and ensure data integrity.

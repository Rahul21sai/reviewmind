# TEAM_STYLE.md

## What we care about
- **Design Patterns:** Consider using a design pattern for clarity and maintainability.
- **Function Decomposition:** Break large functions into smaller, manageable pieces.
- **Inline Comments:** Add comments to explain complex or unclear lines of code.
- **Logging:** Implement logging before and after critical operations to track execution flow.
- **Context Managers:** Use context managers for handling file and database operations to ensure proper resource management.
- **Input Validation:** Validate inputs before writing to the database to prevent errors.
- **Named Constants:** Replace magic numbers with descriptive named constants for better readability.
- **Parameterised Queries:** Always use parameterised queries to prevent SQL injection vulnerabilities.
- **Specific Exception Handling:** Surround API calls with specific exception handling to manage errors gracefully.
- **Descriptive Variable Names:** Use clear and descriptive variable names instead of single-letter identifiers.

## What we ignore
- **Unit Tests for Helpers:** Do not feel obligated to add unit tests for simple helper functions.
- **Local Type Hints:** Avoid adding type hints for every local variable.
- **Module Documentation:** Refrain from adding excessive documentation to modules.
- **Repeated Logic Extraction:** Do not extract repeated logic into helper functions.
- **Manual Indexing Alternatives:** Avoid using `enumerate` over manual index tracking.
- **Guard Clauses:** Not necessary to add guard clauses if they complicate the flow.
- **Path Libraries:** Do not prioritize `pathlib.Path` over `os.path` for file operations.
- **String Formatting Preferences:** Avoid enforcing f-strings over string concatenation.

## Naming conventions
- Use descriptive and meaningful names for variables and functions that convey their purpose.

## Error handling
- Use specific exception handling around potentially faulty operations (e.g., API calls) to avoid broad application crashes.

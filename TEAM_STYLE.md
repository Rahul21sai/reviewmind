# TEAM_STYLE.md

## What we care about
- Add unit tests for all helper functions.
- Consider using appropriate design patterns.
- Use type hints for every local variable.
- Break complex functions into smaller, manageable pieces.
- Increase documentation across all modules.
- Include inline comments for clarity on specific lines.
- Implement logging before and after critical operations.
- Extract repeated logic into helper functions.
- Use `enumerate()` to avoid manual index tracking.
- Validate inputs prior to database writes.
- Replace magic numbers with named constants.
- Use parameterized queries to prevent SQL injection.
- Add specific exception handling for API calls.

## What we ignore
- Comments that could cause confusion, particularly those related to sensitive values (e.g., GITHUB_WEBHOOK_SECRET).
- Rejected practices such as guard clauses for reducing nesting depth.
- Preference of `pathlib.Path` over `os.path` for file operations.
- Using f-strings over string concatenation.
- Type hints on public function signatures.
- Returning structured JSON errors from API endpoints.
- Use of context managers for file and database operations.

## Naming conventions
- Use clear and descriptive names for functions, variables, and classes.
- Follow consistent naming patterns (lowercase_with_underscores for functions and variables, CamelCase for classes).

## Error handling
- Implement specific exception handling for anticipated error scenarios.
- Use logging to track and debug errors as they occur.
- Avoid silent failures; ensure exceptions are logged and handled appropriately.  

This style guide reflects our team's coding preferences and aims to foster code quality through clarity, maintainability, and reliability.

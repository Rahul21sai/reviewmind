# TEAM_STYLE.md

## What we care about
- **Design Patterns**: Consider using a design pattern where appropriate.
- **Function Modularity**: Break functions into smaller, manageable pieces.
- **Documentation**: Add more documentation for modules and inline comments for clarity.
- **Logging**: Implement logging before and after critical operations to trace execution flow.
- **Context Managers**: Use context managers for handling file and database operations.
- **Input Validation**: Validate inputs before writing to the database to ensure data integrity.
- **Constants over Magic Numbers**: Replace magic numbers with named constants for clarity.
- **SQL Safety**: Use parameterized queries to prevent SQL injection attacks.
- **Descriptive Naming**: Prefer descriptive variable names instead of single-letter variables.
- **Specific Exception Handling**: Enclose API calls with specific exception handling to manage errors gracefully.

## What we ignore
- **Unit Tests**: Adding unit tests for helper functions is not prioritized.
- **Type Hints**: No requirement for type hints on every local variable or public function signatures.
- **Logic Extraction**: Extracting repeated logic into helper functions is not emphasized.
- **Index Tracking**: Manual index tracking should not be replaced with enumerate.
- **Guard Clauses**: No requirement to add guard clauses to reduce nesting depth.
- **File Operations**: Preference for pathlib.Path over os.path is not enforced.
- **String Formatting**: No strict preference for f-strings over other string concatenation methods.

## Naming conventions
- Use descriptive variable names to enhance code readability.
- Avoid using single-letter variable names unless in loop counters or index contexts.

## Error handling
- Surround critical sections, such as API calls, with specific exception handling to better manage errors and provide clearer debugging information.

## What we care about
- Ensure the `GITHUB_WEBHOOK_SECRET` value is free of extraneous text.
- Add logging before and after critical operations.
- Extract repeated logic into helper functions.
- Use `enumerate()` to avoid manual index tracking.
- Implement guard clauses to reduce nesting depth.
- Prefer f-strings over string concatenation for better readability.
- Return structured JSON errors from API endpoints.
- Utilize context managers for file and database operations.
- Perform input validation before database writes.
- Replace magic numbers with named constants for clarity.
- Use parameterized queries to prevent SQL injection.
- Implement specific exception handling around API calls.
- Choose descriptive variable names instead of single letters.

## What we ignore
- Unit tests for helper functions.
- Suggestions to consider design patterns.
- Type hints for every local variable.
- Breaking functions into smaller pieces whenever possible.
- Requests for additional documentation on modules.
- Inline comments for clarity on single lines.
- Prefer `pathlib.Path` over `os.path` for file operations.
- Type hints on public function signatures.

## Naming conventions
- Use clear and descriptive names for variables and functions.
- Avoid single-letter variable names; they should reflect their purpose.

## Error handling
- Always return structured JSON errors from API endpoints.
- Implement specific exception handling around API calls to improve reliability.
